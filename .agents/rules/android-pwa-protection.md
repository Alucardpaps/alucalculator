# Android / Wear OS TWA Protection

**Suggested activation: Glob — `android/**`, `android-wear/**`.**

## What this actually is

Both directories are generated by `@bubblewrap/cli`, wrapping the live site in a Trusted Web Activity — confirmed via `android/twa-manifest.json`: package `com.alucard.alucalcos`, `startUrl: /workspace`, pointing at `https://www.alucalculator.com`. This is a thin remote WebView shell (~1.16 MB), **not** a bundled offline engine — see `PHASE0.md`'s decision record (`DESKTOP=SKIP`). Perceived slowness on mobile is network round-trips for uncached assets, not a native-app limitation — the fix is PWA service-worker precaching, not native rework.

## Rules

- Don't structurally modify `android/` or `android-wear/` (regenerate via Bubblewrap instead of hand-editing generated project files) unless the task is explicitly about the native wrapper.
- Never commit `*.keystore` — this is the active incident in these exact directories; see `security-hardening.md`.
- Changing `public/manifest.json`, `public/sw.js`, or app icons can desync the TWA config (`twa-manifest.json`, digital asset links) — flag this rather than assuming it auto-updates.
- `iconUrl`/`maskableIconUrl` in `twa-manifest.json` currently point at `http://localhost:8585/...` — a local Bubblewrap build-time fetch target. Normal for Bubblewrap's build process, but not portable to a fresh machine or agent session as-is. Don't "fix" it to a production URL without first checking what Bubblewrap actually expects at build time.
- "The app feels slow" is a `.agents/rules/performance-guardrails.md` + PWA-precache-scope problem, not something this directory can fix on its own.
